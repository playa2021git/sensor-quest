# SENSOR QUEST — 最適なセンサを選べ！

中学校3年生・技術科「計測・制御」「技術による問題解決」の導入教材。身近な10場面で、取得できる情報・限界・費用・構成の複雑さを比較します。タイトル → 問題 → 解説 → 結果 → 問題ごとの復習まで実装しています。

## 起動

ビルド、CDN、データベース、ログイン、APIキーは不要です。Python 3がある場合：

```sh
python3 -m http.server 4173
```

ブラウザで `http://localhost:4173/` を開きます。ES Modulesを使うため、ファイルをダブルクリックする `file://` 起動ではなくローカルHTTPを利用してください。配信後のゲームは外部サービスへ接続せず動作します。初回のページ取得後に完全オフライン再読み込みを保証するPWAではありません。

## GitHub Pages

PRを確認してmainへマージした後、GitHubの **Settings → Pages → Build and deployment → Deploy from a branch → main / (root)** を選択します。公開予定URLは `https://playa2021git.github.io/sensor-quest/`。HTML・CSS・JS・画像はすべて相対パスで読み込みます。独自のサーバやビルド処理は不要です。このPRではPages設定の変更、mainへの直接push、自動マージは行いません。

## 操作と学習

- マウス、タッチパッド、A〜Eキー、Tab＋Enterで回答できます。選択肢は毎回シャッフルし、採点は位置ではなくIDで行います。
- 最適 `optimal` は2点、実現可能 `possible` は1点、条件に不適切 `unsuitable` は0点。時間切れは別区分 `timeout` として0点で記録し解説を表示します。速度による加点はありません。
- 初期設定は1問60秒。設定で制限をなくせます。時間設定の変更は次問から適用。ダイアログ表示中も時計は進み、タブを離れても締切時刻を基準に残り時間を更新します。
- 音量は初期ミュート。正解時の短い猫の演出を設定で無効化でき、OSの動きを減らす設定にも従います。全画面ボタンがあります。
- 10問・20点満点。ランクはS:18〜20、A:14〜17、B:10〜13、C:0〜9点。得点は理解の参考であり成績評価ではありません。
- 結果画面から全問、または最適でなかった問題を選んで、自分の選択と最適解を比較できます。満点時も全問の解説を確認できます。
- 1366×768、1280×720の横長画面が対象。問題と選択肢はページの縦スクロールなし。解説の「他の選択肢」、図鑑のダイアログは内容に応じて欄内スクロールを使います。スマートフォン最適化は対象外です。

回答履歴は実行中のメモリだけで保持し、再読み込みで消えます。設定だけをlocalStorageへ保存。氏名・出席番号は収集せず、回答の外部送信やアクセス解析を行いません。保存不可の環境でもゲームは動作します。

## ファイル構成と編集

```text
index.html            エントリ
src/app.js            画面と状態遷移、タイマー、操作
src/engine.js         採点・集計・シャッフル（DOMに依存しない）
src/questions.js      10問のデータ
src/encyclopedia.js   16項目のセンサ図鑑
src/style.css         工房の背景、UI、指定解像度の調整
assets/*.svg          オリジナルの猫と場面図
```

問題の `id / stage / title / scenario / requirements / image / choices / evaluation / explanation / limitations / learningPoint / sourceNotes` を編集します。各choiceには固有ID、label、evaluation、information、explanation、limitationsが必要です。採点にはchoiceのevaluationを使います。1問につき5択、最適は1つにしてください。各問の最適解は「与えた条件・候補の範囲内での最適」であり、絶対的な唯一解を意味しません。

現状は10問固定（進行・得点上限・文言も10問）。11問目以降を出題する場合は、データを加えるだけでなく `app.js` の10問固定の終端と文言、満点とランクも変更してください。

### 画像の差し替え

添付の参考画像はチャット上の視覚参考として利用し、リポジトリには画像が入っていないことを確認しました。参考画像を転用せず、独自のSVGを作成しています。

猫は `assets/cat-normal.svg`（通常）、`cat-explain.svg`（説明）、`cat-success.svg`（成功）、`cat-improve.svg`（改善提案）、`cat-result.svg`（結果）。作業着・安全ヘルメット・緑十字・黄色い目の灰色猫です。解説用ポーズも差し替え可能です。場面図は `soap.svg / door.svg / light.svg / robot.svg / car.svg / water.svg / bottle.svg / bed.svg / box.svg / sound.svg`。別形式なら `questions.js` のimageを変更します。縦横比はobject-fit:containで維持し、場面図が欠けても代替表示を出します。

## 技術的な比較と出典

確認日：2026-11-13。メーカーの写真・本文は転載していません。具体的製品の採用方式と、本教材の条件付き最適解は区別しています。

- **第1問**：架空の近距離反射型の構成です。光が手で反射して戻る説明を用い、遮光型と混同しません。特定のソープ製品の採用方式は断定しません。
- **第2問**：[NABCO EAGLE1](https://nabco.nabtesco.com/products_detail/eagle/) の動体検出・マイクロ波ドップラー方式、[Hotron SSR-3](https://hotron.com/product/ssr-3/) のマイクロ波＋能動赤外線による起動・安全検知を確認。動く人を検知する起動センサと、停止中の人を保護する存在検知は別の役割です。問題は起動側に限定し安全センサの別設置を条件にしています。
- **第3〜5問**：基本原理に基づく授業用比較です。LiDARの地図作成には自己位置推定などの処理も必要です。超音波や光学式の有効距離、透明物や細い障害物への応答は型番・設置条件で異なります。駐車支援は安全確認を代替しません。
- **第6・7・10問**：[Google Teachable Machine](https://teachablemachine.withgoogle.com/) の画像・音声プロジェクトを想定した設計問題。ゲーム内でカメラやマイク、学習モデルは起動しません。学習済み分類器の利用方法を考える教材です。猫・犬、物品、通常音・異常音・背景音は実際の環境でデータを集め、未知データでも確認する必要があります。
- **第8問**：荷重で在床を推定する条件です。睡眠状態を測定しているとは扱いません。
- **第9問**：授業用試作品の構成です。通常の画像分類は確実な本人認証ではありません。登録タグも複製耐性や紛失対策、機械的強度・停電・故障への対策が別途必要で、実用防犯性能は保証しません。

## 検証

Node.js 20以上（開発時のみ）で：

```sh
npm test
```

10問・5択・最適解1つ・IDの一意性・必須データ・画像存在、3段階採点、時間切れ、満点、混合集計、シャッフルの妥当性を検証します。

ブラウザ検証はPython 3とPlaywrightが必要です。`npm ci` 後、Chromiumが `/usr/bin/chromium` にない場合は `CHROMIUM_PATH` に実行ファイルを指定してください。必要なら開発環境で `npx playwright install chromium` を実行してそのパスを指定します。

```sh
npm run test:browser
```

テストがローカルHTTPをポート4175で起動・終了します。リポジトリ名のサブディレクトリから配信し、1366×768・1280×720の両方で10問完走、最適・可能・不適切の混合採点（11/20）、二重回答防止、キー回答、結果、全問復習、再挑戦、図鑑、遊び方を確認。Playwrightの仮想時計で60秒の時間切れと無制限設定を検証し、画像リクエストを失敗させて代替表示を確認します。画面のはみ出しとJS例外も検出。スクリーンショットと結果JSONは無視対象の `work/` に出力します。

開発環境のChromiumで上記を実行し、データ/採点テスト3件およびブラウザ検証は成功しました。実機ChromeOSでの確認とGitHub Pages本番公開後の確認は未実施です。
